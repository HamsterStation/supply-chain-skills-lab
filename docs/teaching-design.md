# 教学设计

用户后续选择 GitHub Pages，并要求每位学习者用自己的 GitHub 登录和仓库保存。公共内容与个人学习数据必须分开。不得导入作者其他项目的课程或记录。

每课流程：具体业务问题 → 原创完整示例 → 方法及计算 → 补步骤 → 独立小任务 → 固定反馈与复盘。完整阅读和逐步带练都可自由跳转，不锁课。每课有目标、先修、提示、解析、变式、误解、来源与限制。

数值题使用固定规则，不调用模型。看过提示或解析后正确作答记为 assisted；未查看过该题该版本提示的正确作答才记为 independent。变式有独立题目 ID。阅读、自评掌握、待复习、跳过等都是本站学习状态，不是职业资历认证。每次作答和状态事件追加保存。

开放决策按数据、计算、约束、假设、风险、替代方案与行动评价，不因供应商名称或库存策略与参考不同而判错。首版提供自查评分维度，不伪装成 AI 专业评分。AI 辅导未启用。

默认复习间隔 3 天，允许在 1–365 天内调整。少量到期复习出现在首页；不会用浏览时长声称能力达标。路线按共同基础、所选方向、先修关系解释推荐。手动排序后不被新内容或画像修改静默重排。行业、地区和经验只作学习背景，不制造个性化置信分。

## 公式与数据

预测只用预测时点已经知道的历史。选择模型与最终测试分开。MAE 的单位与需求相同；实际为零时不计算 MAPE。库存案例使用最近 28 个完整自然日需求，种子 20260922。IP=现有+在途−欠交，需求预测不重复包含欠交；定期检查保护期 R+L；经验缓冲不能宣称达到特定服务水平。无约束需求不应被实际缺货后的销售额替代。

库存参考表按原始数据计算，不用屏幕显示的四舍五入均值。建议量向上取整。参考 CSV、字典与 JSON 全部公开，生成器无随机外部依赖。

供应商案例比较货款与每单运费，数量考虑 MOQ（最小起订量），没有包装倍数条件。排除税费、资金、仓储、质量损失、报废等，不称完整 TCO。时间单位为自然日。丙的质量尚待样品确认；不能仅凭较短交期认定完全可行。

系统相关内容只是物料与计划数据关系原理，不是 SAP/IBP 操作认证或模拟商业系统实训。
