# 内容与证据规范

本站以业务能力优先，A–H 是本站组织体系，不是官方认证体系。首版为 18 张技能卡、8 节完整课程和 2 个原创合成案例。`source_checked; subject_matter_review_pending` 表示已核查来源，不表示专业专家已签字或机构认可。

每份内容用稳定 ID 和递增整数版本。不得以标题、数组位置作永久标识。历史作答保留题目和案例快照，不因课程升级删除。

## 证据边界

优先原始框架、公开教材、具名研究、官方文档和企业第一手材料。证据必须分别填写 `source_claim`、`editorial_recommendation`、`uncertainty`。单个岗位或来源只支持其具体范围，不是全球行业共识。转载用原始 URL 和内容哈希去重，不算独立证据。厂商材料必须标明厂商主张。

发布日期未知填 null。2006 年 MIT 教学讲义仅支持基础方法，不能作为当前软件操作、运价、贸易规则或最新版 SCOR 的证明。首版不讲现行法律、税率或地区贸易规定。以后新增必须记录地区、版本、生效日期及复核日期。

原始来源保留链接、定位和哈希，不镜像教材全文。MIT PDF 的哈希为 HTTP 响应字节；CIPS 本次通过公开浏览文本核查，但直接程序访问返回 403，所以其哈希明确只针对登记的短摘录（`verified_short_excerpt`），不是声称拿到了被阻挡的全文。自动程序不得绕过 403、登录、验证码、付费墙或 robots。

专家身份必须由公开署名和作品证明。不得因职位或雇主推断个人工具水平。当前引用 Chris Caplice 的具体讲义与 Hyndman、Athanasopoulos 的具体预测教材，不做人物排名。

岗位证据必须有角色、地区、经验、发布日期、核查日期、失效日期、原始岗位 ID，并区分必需、优先和职责；失效岗位不算当前需求。企业成效数字必须有指标、基线、时间范围和限制，否则不写数字。当前没有未经核验的招聘条目或企业成果。

## 自动化边界

自动提案只允许新增 `content/updates/*.json`，状态必须为 draft，禁止覆盖人工课程正文。独立状态分支仅允许受控脚本写 `content/updates/collector-state.json`，不合并到发布分支、不包含个人记录。模型供应商默认 disabled；不向模型发送个人记录，也不让外部页面指令控制代码写入。

草稿先记录变化及定位待核查，不能冒充已提取的新专业结论。路线调整使用独立 `route_proposal`，须人工决定，不自动修改学习者的路线。无变化不创建 PR。审核人应补充准确结论、适用对象和证据，再决定是否发布。

内容以 JSON 和纯文本存储；React 转义文本；拒绝危险 HTML、未知字段、可执行 MDX、路径穿越和符号链接。CSV 只包含本站合成数据；用户不上传企业文件。
